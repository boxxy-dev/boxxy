# Preferences Crate (`boxxy-preferences`)

## Responsibility
Manages application settings, persistence, and the Preferences UI. This crate ensures that user configurations (font, theme, API keys, etc.) are correctly saved to disk and applied across all components.

## Architecture
The crate uses a modern, declarative UI approach:

- **`config.rs`**: Defines the `Settings` struct, default values, and JSON serialization logic (`~/.config/boxxy-terminal/settings.json`).
- **`component.rs`**: Implements the `PreferencesComponent` using an **`AdwNavigationSplitView`** architecture. This provides a left sidebar for categories and a right-pane content area.
- **`resources/ui/preferences.ui`**: The entire widget tree is defined in this GtkBuilder XML file, which is loaded at runtime.

## Key Features
- **Categorized Navigation**: Settings are grouped into Terminal (Appearance, Terminal, Cursor, Layout, Previews), Themes (Boxxy Official Themes `Boxxy Dark` / `Boxxy Light`, Accent Color overrides, Community `.toml` Themes in `~/.config/boxxy-terminal/themes/`, and Legacy Adwaita Themes), APIs, Characters, Desktop Integrations, MCP, Skills, Claw UI & Sounds, Toolbox & Permissions, Shortcuts, Advanced, and About sections.
- **Real-Time Search**: A global search entry in the sidebar filters both categories and individual setting rows dynamically.
- **Dynamic API Support & OpenAI-Compatible Endpoints**: The APIs section displays only configured built-in catalog providers on the front page (each with an inline `PasswordEntryRow` and a remove button) alongside an **Add Provider…** action row that opens a sub-page (`apis/catalog_provider_dialog.rs`) listing all unconfigured catalog providers with per-row `Add` buttons (removing each provider from the sub-page as soon as it is added). It also includes an **OpenAI-Compatible Endpoints** group (`apis/openai_compat_dialog.rs`) for adding/editing custom endpoints (with presets for OpenCode Go, OpenCode Zen, LiteLLM, and local vLLM/llama.cpp, live `/models` fetching, and per-model context/thinking/cost overrides). Keys are stored in `api_keys` or resolved from environment variables.
- **Master Capability Switches & Vibe Mode Trusted Locations**: Settings like `enable_web_search` act as hard locks on agent capabilities. This implements the "Master Switch vs Local Toggle" design pattern, ensuring that even if a feature is toggled on locally in a pane, it is strictly forbidden unless the global preference allows it. The `Toolbox & Permissions` page also configures `max_roundtable_turns` (`Character Chat Turn Limit`, default `20`, range `1..=100`) to cap autonomous character-to-character turns in multi-character chats/debates, and manages `vibe_trusted_dirs` (`Vibe Mode Locations`), allowing users to add, browse, and remove trusted workspace folders (with subdirectory inheritance and validation blocking `/`, bare `$HOME`, and system directories) where Vibe Mode can auto-execute safe commands and file edits.
- **Off by Default Strategy**: Supports a "Lightweight First" philosophy. Users can toggle `web_search_by_default` in settings to ensure heavier tools only load when explicitly requested, preserving system resources and API credits. Agents themselves initialize in an inactive state and require manual activation or interaction to wake.
- **Automatic Persistence**: All changes are saved to disk via generation-stamped atomic temp files (`settings.json.<pid>.<gen>.tmp`) and broadcasted through `SETTINGS_EVENT_BUS` only after the atomic rename completes.
- **Lock-Free Cache & Cross-Process Sync**: `Settings` is cached in a lock-free `LazyLock<ArcSwap<Settings>>`. `Settings::load()` returns an `Arc<Settings>` via an atomic pointer load (zero cloning for readers), and `Settings::update(|s| ...)` performs atomic RCU updates. `Settings::init()` hydrates the cache from disk at startup; `Settings::reload()` re-reads and swaps the cache so the daemon picks up UI-side saves without restarting.
- **Experimental Toggles**: The `Persistent Shells (Experimental)` switch in Advanced → Shell corresponds to the `pty_persistence: bool` field (default `false`). When on, closing a pane detaches its shell into the daemon instead of killing it; the infrastructure is complete but the reopen/reattach UI isn't built yet.
- **Desktop Integrations**: The `Desktop Integrations` page (`integrations/mod.rs`) groups desktop environment companions under **GNOME** and **COSMIC**. The **Nautilus Integration** switch corresponds to `nautilus_integration: bool` (default `true`); on startup (`Settings::ensure_claw_skills()`) and when toggled, `Settings::sync_nautilus_extension` installs or removes the embedded `resources/nautilus/open_with_boxxy.py` extension at `~/.local/share/nautilus-python/extensions/open_with_boxxy.py`. It also links to the official GNOME Shell Extension (`https://github.com/boxxy-dev/gnome-shell-boxxy-companion`) and COSMIC Boxxy Companion (`https://github.com/boxxy-dev/cosmic-boxxy-companion`).
- **Skills Page (`skills/mod.rs`)**: Located under MCP in the Preferences sidebar. Lazily scans skill frontmatter headers (`boxxy_claw_protocol::skill_loader::discover_skill_summaries`) when the page is mapped, lists current skills with per-skill Enable/Disable switches (`disabled_skills: Vec<String>` in `Settings`), provides an **Open Skills Folder** row for creating or removing skills in the file manager, and displays a subtle **Add a Skill** action row when no skills exist yet. On startup (`Settings::ensure_claw_skills()`), the bundled `boxxy-theme-creator` `SKILL.md` is unconditionally overwritten to disk so skill updates ship automatically while preserving the user's enabled/disabled toggle.
- **Claw UI Page**: `claw_ui/mod.rs` binds the Claw UI preference rows. The dimension settings (`claw_popover_width`, `claw_popover_max_height`) and their `CLAW_*_BOUNDS` consts were removed when the drawer redesign landed — the drawer is pane-sized, not user-sized. What remains: `overlay_bottom_gap` (leave an 80 px gap below the drawer so the terminal stays visible behind it, default `true`), `enable_tips`, `overlay_font_scale` (percentage SpinRow `60%..=220%` step `10%`, synced live with `Ctrl++`/`Ctrl+-`/`Ctrl+0` inside the overlay), `currency` (searchable `AdwComboRow` for session spend currency: USD, EUR, CNY, INR, BRL, defaulting to USD), and `claw_msgbar_shortcut` (the accelerator that opens the drawer, default `<Ctrl>slash`).
- **UI Decoupling**: Logic is separated from the UI layout by using GResource-based XML templates.
