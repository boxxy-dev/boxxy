# Boxxy-MCP Architecture & Guidelines

## Component Overview
The `boxxy-mcp` crate provides a Model Context Protocol (MCP) client integration for Boxxy-Terminal built directly on `rmcp 3.12.0` (supporting the MCP `2026-07-28` specification via `server/discover` as well as `2025-11-25` and earlier servers via `initialize`). It bridges MCP servers (JSON-RPC + JSON Schema Draft 7 / 2020-12) to `rig` (`rig 0.47.1` `DynamicTool`).

> **Why `rmcp` Directly Instead of `rig-rmcp`:** `rig-rmcp` wraps `rmcp` with legacy `initialize`-only startup (`ProtocolVersion::LATEST_WITH_INITIALIZE`), retires tools permanently on disconnect instead of reconnecting, omits `$schema` / empty-object schema normalization and `FastMCP` deduplication, and provides no pre/post `McpToolObserver` hooks for Boxxy's live Claw indicator pill, sidebar debug rows, and telemetry. `boxxy-mcp` retains direct `rmcp 3.12.0` lifecycle control while incorporating `rig 0.47`'s typed `ToolExecutionError`s, `ToolAnnotations` (serialized safely as `Touches::Writes` on `DynamicTool`), capability checks, native `ToolOutput::json` + contentless `CallToolResult` support, and multimodal `ToolOutput` image forwarding.

## Module Layout & Feature Gating
- **`Cargo.toml` (`runtime` feature):** Default `runtime` feature enables `rmcp`, `rig`, `tokio`, and `reqwest`. Config-only consumers (`boxxy-preferences`, `boxxy-cli`) depend on `boxxy-mcp` with `default-features = false` so UI/CLI crates compile pure `serde` DTOs (`config.rs`) without pulling in the MCP/AI runtime stack.
- **`config.rs`:** `McpServerConfig`, `McpTransport` (`Stdio` / `Http`), and `BackoffConfig` with clamped timeout and finite exponential-backoff helpers.
- **`client/` (`error.rs`, `handler.rs`, `stdio.rs`, `http.rs`):**
  - `handler.rs`: `Arc<str>`-backed `BoxxyClientHandler` advertises `boxxy-terminal` with `ProtocolVersion::LATEST_WITH_INITIALIZE` for stateful Stdio handshakes and invalidates `McpClientManager`'s generation-stamped tool cache on `notifications/tools/list_changed`.
  - `stdio.rs`: Validates non-empty commands via `rmcp::transport::which_command`, scrubs `boxxy_sys_utils::env::scrubbed_pty_var_names()` session/dev markers before applying user `env` overrides, pipes and drains child `stderr` continuously (preventing pipe-full deadlocks and daemon stderr noise while surfacing up to 2 KiB of trailing `stderr` diagnostics if initialization fails), preserves typed `ClientInitializeError`s in `anyhow`, and wraps child processes in `TokioChildProcess` (`kill_on_drop(true)` + `SIGTERM`-first `graceful_shutdown`).
  - `http.rs`: Uses `ClientLifecycleMode::Auto` (`2026-07-28` `server/discover` -> `2025-11-25` `initialize` fallback), same-origin `307`/`308` redirect policy, UTF-8-safe `Authorization` parsing (routing `Bearer` / raw tokens to `auth_header` while preserving `Basic` / `ApiKey` / `Token` schemes verbatim in `custom_headers`), `tcp_nodelay(true)` + HTTP keep-alive pooling for remote servers (with `pool_max_idle_per_host(0)` for loopback and `*.localhost` dev servers, omitting client-wide `.timeout()` so stateful `2025-11-25` SSE GET notification streams are never severed between events), and sub-millisecond TCP loopback liveness probes.
  - `error.rs`: Unified recursive error-tree walker covering `ClientInitializeError` and `ServiceError` chains, `PermanentConfigError`, `reqwest::Error::is_connect()` / `ConnectionRefused` detection, `ReservedHeaderConflict` classification, `SessionExpired` and `ListPaginationExceeded` diagnostics, `HttpStatusError` (`Retry-After`), `ResponseBodyTooLarge` diagnostics, and `401`/`403` `WWW-Authenticate` + `InsufficientScopeError` challenge reporting via `rmcp 3.12`'s `ClientInitializeError::auth_challenge()` and `ServiceError::auth_challenge()`.
- **`manager/` (`mod.rs`, `breaker.rs`, `tests.rs`):**
  - Per-server single-flight connection (`connect_locks`) and tool-list (`tool_fetch_locks`) locks prevent duplicate Stdio process spawns, racing HTTP handshakes, or duplicate cold `tools/list` RPCs under concurrent calls.
  - Honors `rmcp 3.12`'s merged SEP-2549 `ttlMs` hints (including fractional/numeric normalization and 64-page cursor cap) across paginated `list_all_tools_with_cache_hint()` pages (`ttlMs: Some(0)` bypasses caching for dynamic catalogs; positive `ttlMs` bounds retention up to `MAX_CLIENT_CACHE_TTL`; `None` caches stateful sessions until `notifications/tools/list_changed`), paired with generation-stamped `tool_cache` invalidation (`cache_generations`) and `Peer::clear_response_cache()`. Skips `tools/list` on servers whose handshake declared `capabilities.tools == None`.
  - Automatically evicts dead or expired sessions (`evict_if_same_client`, covering both `TransportClosed` and HTTP 404 `SessionExpired`) with a single reconnect retry on mid-turn disconnect during `get_tools`, and immediately evicts + trips `PERMANENT_CONFIG_COOLDOWN` if an active session hits a `401`/`403` `ServiceError::is_authorization_required()` challenge.
  - `get_server_statuses()` and `build_rig_tools()` probe and fetch across all enabled servers concurrently (`join_all`) while sorting server names deterministically to preserve LLM prompt prefix caching.
  - Holds the sole resting strong `Arc<McpClientWrapper>` (`DynamicMcpTool` holds `Weak`), allowing `update_configs()` and dead-session eviction to run `close_with_timeout(7s)` (`SIGTERM` on Stdio, `HTTP DELETE` session cleanup on Streamable HTTP).
  - In-memory circuit breaker (`60s` transient cooldown, `300s` permanent config/auth cooldown, reset immediately when edited in Preferences).
- **`rig_bridge/` (`schema.rs`, `output.rs`, `tool.rs`):**
  - `schema.rs`: Recursively strips `$schema` dialect URIs from root and nested `$defs` / subschemas (preserving any user tool property literally named `"$schema"` and Draft-07 property-name `dependencies` arrays) and injects `"properties": {}` on bare `"object"` and Draft 2020-12 nullable `["object", "null"]` schemas while preserving open dictionary maps (`additionalProperties`, `patternProperties`, `unevaluatedProperties`).
  - `output.rs`: Supports `rmcp 3.11` contentless `CallToolResult`s, preserves non-string SEP-2106 `structured_content` natively via `ToolOutput::json` (deduplicating `FastMCP` mirrors), and forwards multimodal MCP images (`ContentBlock::Image` and image `BlobResourceContents`, normalizing `image/jpg` / uppercase / parameterized MIME types) as `ToolResultContent::image_base64` while keeping compact summaries for `McpToolObserver`.
  - `tool.rs`: Normalizes `{server}__{tool}` names to `^[a-zA-Z_][a-zA-Z0-9_-]{0,63}$` (capping >64-char names with a zero-allocation deterministic FNV-1a hash suffix), rejects non-object/non-null JSON arguments and `-32602` `INVALID_PARAMS` replies via `ToolExecutionError::invalid_args`, forwards `ToolAnnotations`, evicts closed transports, and maps failures to typed `ToolExecutionError::{timeout, invalid_args, provider, other}` with `.with_model_output(...)`.
