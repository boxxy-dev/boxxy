# Viewer Crate (`boxxy-viewer`)

## Responsibility
Provides a **headless**, unified GTK4 rendering library that transforms raw text (Markdown), JSON, and Custom Proposals into rich, native UI widgets.

The term **headless** in this context means that the `viewer` crate is completely agnostic to Boxxy-Terminal's specific business logic. It does not know what a "Claw Agent" is, nor does it interact with the PTY or terminal. It is a pure UI library that other Boxxy components (like the sidebar or terminal overlays) use to render structured data efficiently.

## Architecture
The crate operates as a pipeline: `Raw String Input` -> `Parser` -> `Abstract Syntax Tree (ContentBlock)` -> `BlockRenderer` (`render_with_context` / `update`) -> `gtk::Widget`.

### 1. Abstract Syntax Tree (`ContentBlock`)
Instead of treating everything as a single string, the viewer splits input into distinct, logical blocks (`Paragraph`, `Heading`, `Blockquote(Vec<ContentBlock>)`, `List { ordered, start, items }`, `Rule`, `Image`, `ImageGallery`, `Table`, `Code`, `Custom`).
- **Balanced Inline Tag Stack & Streaming Resilience:** Tracks active inline styles (`<b>`, `<i>`, `<s>`, `<a href="...">`) across `Image` paragraph splits and partial streaming EOF boundaries, discarding tag-only wrapper paragraphs so clickable badge images (`[![badge](img.svg)](url)`) and styled inline images always emit valid Pango XML.
- **Nested Blockquotes & Custom List Starts:** `ContentBlock::Blockquote` holds nested `ContentBlock` children (preserving document order for lists, code blocks, headings, and nested quotes inside `>`), and `ContentBlock::List` preserves CommonMark's `start` index.
- **Automatic Gallery Coalescing with Zero-Image Fast Path:** Post-processes media lists and consecutive standalone `ContentBlock::Image` entries into `ContentBlock::ImageGallery { items: Vec<GalleryItem> }`, while skipping coalescing completely (`may_have_gallery_candidates`) on non-image turns so AST blocks are never cloned unnecessarily.
- **GFM Table Parsing:** Full support for GitHub-Flavored Markdown tables (`Tag::Table`, `TableHead`, `TableRow`, `TableCell`), including streaming partial tables, inline `<br>` / `<br/>` line breaks, and images embedded directly inside table cells (`TableCell { markup, images }`).
- **Clickable Hyperlinks:** Converts Markdown links `[text](url)` into Pango `<a href="...">` tags wired to `gtk::UriLauncher` (for web URLs) and `gtk::FileLauncher` (for local files).

### 2. Extensible Renderers (`BlockRenderer`, `RenderContext` & `ViewerRegistry`)
The crate uses a plugin architecture with lifecycle-aware `RenderContext` (`generation` + `is_streaming`) and in-place `BlockRenderer::update` support so active streaming blocks and recycled `GtkListView` rows mutate existing GTK widgets in-place instead of destroying and recreating GObjects.
- `CodeRenderer` & `CodeBlockWidget` (`renderer/code.rs`): OpenCode V2-aligned fenced code block renderer (`.viewer-code-block`):
  - Renders at full natural vertical height (never collapsed or height-capped) with horizontal-only scrolling, strips the phantom trailing CommonMark `\n` from display while copying exact raw source, overlays a subtle language pill + hover-revealed floating Copy button in the top-end corner, and styles shell snippets (`bash`, `sh`, `shell`, `zsh`, `fish`, `console`, `terminal`) in clean monochrome (`.viewer-code-shell`).
  - Uses raw `set_text` + coalesced `pango::AttrList` foreground spans (`HighlightedCode` / `SyntaxSpan`, ~35× smaller than Pango XML markup with zero main-thread XML parsing).
  - Splits files exceeding `VIRTUALIZE_LINE_THRESHOLD` (`200` lines) into `100`-line `GtkLabel` slices inside the horizontal scroller so GTK4/GSK frustum-culls off-screen slices during fast scrolling, and guards `syntect` against minified lines (`> 2 KiB`) and giant blobs (`> 500 KiB`).
  - Uses a stateful `stable` + `unstable` line lexer (`StreamCodeLexer`) during 60 Hz streaming so only newly appended lines are lexed per tick (committing to `HIGHLIGHT_CACHE` on stream completion), checks parent `generation` for background cancellation, and tracks `"boxxy-card-is-dark"` in `WidgetImpl::snapshot` for hybrid Boxxy themes.
- `TableRenderer` (`renderer/table.rs`): Renders GFM tables inside a `.viewer-table-frame` card using a `HeightForWidth` `TableContainer` around `gtk::Grid` (preventing unconstrained 1-character minimum-width height inflation inside horizontal `GtkBox` rows), alternating row shading, smart prose wrapping, embedded `.viewer-image-card` thumbnails inside cells, and lazy on-click Copy TSV formatting via single-pass `strip_pango_markup`.
- `ImageRenderer` (`renderer/image.rs`): Renders standalone (`<= 320×200`) and table-cell (`<= 200×125`) thumbnails (via `BoundedCard` to prevent `GtkPicture` aspect-ratio height inflation in wide containers) and zero-allocation responsive multi-column `GalleryGrid` media galleries (`.viewer-image-card`, `200..=280 px` wide per card, packing as many columns as fit the pane width with a hover-revealed floating top-right `⋮` options button and full-width unclipped caption strip), with in-flight thumbnail deduplication (`IN_FLIGHT_THUMBS`), weak widget references + generation cancellation on async loads, and 5-second timeout + `kill_on_drop` bounds on `ffmpeg` frame/cover extraction.
- `DiffRenderer` (`renderer/diff/{mod,layout,canvas,drawer,markup}.rs`): Renders `ContentBlock::Custom { schema: "file_diff" | "file_diff_compact", .. }` into a native `.viewer-diff-card` with header stats/actions, a `HeightForWidth` `ResponsiveDiffContainer` switching between Two-Column Split (`>= 460px`) and Compact + Slide-Over Original Drawer (`< 460px` or user-toggled), and a `DiffHunkCanvas` that caches coalesced contiguous vertical `(DiffRowTone, y, h)` rect runs per `(width, height)` for zero-allocation `snapshot()` painting. Pending approval proposals (`"file_diff"`) and small diffs (`<= 12` changed lines) start expanded; auto-approved `"file_diff_compact"` rows with `> 12` changed lines start collapsed and **defer mounting the diff body widget tree until expanded**.

### 3. The GTK Component (`StructuredViewer`)
The primary entry point is `StructuredViewer`, which wraps a `gtk::Box` paired with a bounded per-viewer `WidgetPool` (`Paragraph`, `Heading`, `Rule`, `CodeBlockWidget`). Consuming components can replace content (`set_content`), render incremental non-caching previews (`set_streaming_content`), stream continuously at 60 Hz (`append_markdown_stream`), or park child widgets into the recycling pool on `GtkListView` unbind (`park_for_recycle`).

## Key Performance Features
- **In-Place Diffing & Per-Slot Widget Recycling (`ViewerState`):** Preserves unchanged prefix widgets, mutates compatible blocks in-place via `BlockRenderer::update`, and parks surplus widgets into a per-slot `WidgetPool` so `GtkListView` scrolling rebinds paragraphs, headings, rules, and code blocks with zero GObject allocations.
- **Two-Tier Thumbnail Cache & In-Flight Deduplication (`cache.rs`, `image.rs`):** Tier-1 main-thread `MemoryTexture` LRU (96 entries, 0 ms synchronous hit on `connect_bind`) + Tier-2 persistent `<config_dir>/cache/thumbnails/<sha256>.bxt` disk cache + `tokio::sync::watch` in-flight deduplication.
- **Collision-Safe Borrowed-Lookup Caches (`cache.rs`, `diff/markup.rs`):** `SimpleLru::get_by` checks 64-bit hashes first and verifies exact `&str` equality on match (zero allocations on lookup, zero hash-collision risk) across `AST_CACHE` (512 entries), `HIGHLIGHT_CACHE` (512 `Arc<HighlightedCode>` entries), and `DIFF_CACHE` (128 `Arc<PreparedDiff>` entries).
