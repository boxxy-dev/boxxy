# Window Crate (`boxxy-window`)

## Responsibility
Acts as the main UI orchestrator for Boxxy-Terminal. It manages the application window, sidebar, and high-level routing of messages between components.

## Architecture
This crate follows a modular **Model-View-Update (MVU)** architecture:

- **`state.rs`**: Central state definition (`AppWindowInner`) and the `AppInput` message enum.
- **`ui.rs`**: GTK widget tree construction and signal-to-message mapping.
- **`application_detector.rs`**: Pure-Rust application category detector (`ApplicationCategory`, `TerminalAppState`, `detect_application_state`) combining foreground process inspection (with `/proc/<tpgid>/cmdline` wrapper resolution in `boxxy-agent`) and VT alternate-screen mode (`?1049h` / `?1049l`) to classify active terminal sessions into `Idle`, `Editor`, `Monitor`, `AiAgent`, `Git`, `FileManager`, `Pager`, `Multiplexer`, `Remote`, `GenericTui`, and `RunningCommand` for category-specific tab icons.
- **`tab_title.rs`**: Smart Tab Naming and hover tooltip resolution (`smart_tab_naming` setting, enabled by default). Prioritizes user custom titles, remote SSH host + directory (`host · boxxy-terminal`), foreground commands (`vim`), and directory basenames (`boxxy-terminal`, `Downloads`, `src`) with automatic parent-directory disambiguation (`src · boxxy-terminal`) when multiple tabs share the same title, while exposing the full path in the `AdwTabPage` hover tooltip and tab context menu.
- **`widgets/tab_bar/`** (`mod.rs`, `tab.rs`, `slot.rs`, `strip.rs`, `dnd.rs`): Custom `BoxxyTabBar` (`css_name = "tabbar"`) and `BoxxyTab` (`css_name = "tab"`) backed by `AdwTabView`. Uses deterministic browser-style tab sizing (`DEFAULT_TAB_WIDTH = 250`, shrinking down to `MIN_TAB_WIDTH = 120` before horizontal scrolling), places a `.flat` `+` (`boxxy-plus-symbolic`) New Tab button right after the last tab (gliding smoothly with `200ms` `adw::TimedAnimation` open/close animations), aligns tab-level badges on the left (`[color_dot · Claw/Timer .gpa · Bell .gpa]`) while permanently reserving a `16px` App Category `.gpa` slot immediately before the dead-centered title (`0px` shift on icon fade-in/out), implements `AdwTabBox`'s 2-stage drag-and-drop (Stage 1 `Capture`-phase `GestureDrag` pixel-for-pixel in-bar reorder with `220ms` FLIP neighbor slide animations -> Stage 2 `gdk::Drag::begin` tear-off to move tabs into another Boxxy window or spawn a new window), denies ancestor `GtkWindowHandle` drags on interactive children while keeping empty headerbar space draggable, and binds `.gpa` `gtk4::Svg` category/indicator/bell paintables directly.
- **`update/` Module**: Modular MVU state transition logic:
    - **`update/mod.rs`**: Primary message dispatcher.
    - **`update/tabs.rs`**: Tab lifecycle (open, close, adopt, transfer, grouped session reattach).
    - **`update/tab_bar_sync.rs`**: Direct `BoxxyTab` synchronization for diff-only tab color dot + CSS classes and GPA `.gpa` animated category, Claw/timer indicator, and bell icons. Gates `.gpa` playback and the `RunningCommand` celestial phase timer on `window.is_mapped() && !window.is_suspended()` (`WindowAnimationStateChanged`) so tiled/dual-monitor visible windows stay animated while minimized, workspace-hidden, screen-locked, or occluded Wayland windows schedule zero background frames.
    - **`update/close_dialog.rs`**: Shared 3-button close protection dialog (`Cancel`, `Terminate` / `Terminate All`, `Run in Background`) used by both tab close and window close.
    - **`update/split.rs`**: Split management, layout control, and cross-tab/intra-tab pane drag-and-drop (`move_pane_to_split`, `drop_pane_on_tab`).
    - **`update/events.rs`**: Terminal signal routing, peer pane lookup via `CLAIMS_CACHE`/`CHARACTER_CACHE`, and agent event handling.
    - **`update/claw.rs`**: Claw pane activation, task pause/cancel, soft history clear, session resumption, model selection, and engine reload.
    - **`update/detached_sessions.rs`**: HeaderBar background shells badge and the unified Background Shells dialog.
    - **`update/notifications.rs`**: In-app toast and desktop update notification pipeline, update details dialog, and async character reminder toast widgets.
    - **`update/welcome_dialog.rs`**: First-boot 4:3 full-bleed `AdwDialog` (`840×630`, `resources/ui/welcome_dialog.ui`) playing `resources/videos/welcome.mp4` without player chrome, with floating **Play again** and **Let's Go** controls, `Escape` dismissal, GStreamer teardown on close, and Command Palette re-launch (`win.welcome`).
    - **`update/whats_new_dialog.rs`**: Post-update "What's New" `AdwDialog` controller, commit detail pager, and non-blocking GitHub changelog population.
    - **`update/window_state.rs`**: Window geometry persistence, diff-aware settings synchronization, and sidebar navigation.

## Key Features
- **Task-Aware Closing Protection & Background Detach**: The `handle_close_request` dialog (in `update/window_state.rs`) and tab-close dialog (`update/tabs.rs`) prevent accidental loss of active work. They query `boxxy-agent` for running OS processes, query the `boxxy-claw` `WorkspaceRegistry` for active scheduled AI tasks, AND check `get_active_claw_panes()` for any active AI agent sessions in the tab/window, displaying a unified 3-button alert: **Cancel**, **Run in Background** (detaches running shells and active AI sessions into `boxxy-agent` via `detach_on_close_sync()`), and **Terminate** / **Terminate All** (kills the process group via `terminate_on_close_sync()`). When the "Always Keep Running Processes in Background" (`pty_persistence`) setting is on, the dialog is skipped and running shells / active AI sessions automatically detach into the daemon while idle shells are terminated cleanly.
- **HeaderBar Background Shells Badge**: Whenever one or more detached shells are running in `boxxy-agent`, a flat terminal badge (`detached_btn`) with the active count appears on the right side of the HeaderBar. Clicking the HeaderBar badge opens the unified **Background Shells** `adw::AlertDialog` listing each background shell with **Reattach**, **Terminate**, and **Restore All**.
- **Credential Sync on Save**: Whenever the user saves preferences, `settings_changed` pushes `settings.get_effective_api_keys()` to the daemon via `update_credentials` so the daemon's in-memory state tracks the on-disk file without waiting for the engine's disk-fallback path.
- **Task Indicators**: Automatically manages `adw::TabPage` indicators (e.g., displaying a `boxxy-running-symbolic` clock icon) when a tab contains an agent with pending scheduled tasks, driven by `TaskStatusChanged` events.
- **Multi-Window Support**: Native support for splitting tabs across multiple windows.
- **Advanced Sidebar**: Houses Claw Logs, Bookmarks, and the Theme Selector using a unified `AdwOverlaySplitView`.
- **Frosted Glass**: `widgets/frosted_glass.rs` wraps the entire split view, emits a padded copy/blur/paste backdrop marker (radius 40 for GTK 4.25 compatibility), then paints a separate flat tint. Native `AdwApplicationWindow` clipping owns window corners and CSD geometry; do not add sidebar-dependent corner radii or blur the tint itself.
- **Unified Notification Pipeline & Post-Update "What's New" Dialog**: Manages both local in-app toasts (`ShowToast`) and native OS desktop alerts (`PushGlobalNotification`), using `gtk4::gio::Notification` to ensure proper delivery through Flatpak portals while intelligently suppressing desktop alerts when the window is focused. Update notifications show `"There is a new Boxxy version available"` in the toast and link to the GitHub compare view (`Current Commit` -> `New Commit`) in the details dialog. The first launch after an update consumes `~/.local/boxxy-terminal/.whats_new_pending`, detects a commit transition via `~/.config/boxxy-terminal/last_seen_commit` (for Nix, Flatpak, and distro upgrades), or reads `BOXXY_SIMULATE_UPDATE="commit_a..commit_b"` to present the "What's New in Boxxy" `adw::Dialog` with zero-diff GitHub compare stats (commits, files, lines, and contributor avatars), an interactive commit list that pages the full dialog to show the complete commit message and GitHub commit link, **Read What's New** (starts the Claw overlay with the default character on an idle pane; disabled if no Claw model is configured), and **Ask Another AI**.
- **Global Context Propagation**: The window acts as the primary orchestrator for the **Global Workspace Radar**. It coordinates global intents and orchestration messages to all active terminal peers, regardless of their workspace. Note that Claw mode itself is active **per-terminal pane**, not globally per window. The window observes the active pane's state to update its UI.
- **Intelligent Default State**: Ensures a "Lightweight First" experience while allowing power users to have full agentic assistance by manually activating the agent. New panes start with the agent in an inactive state.
- **Global Event Bus**: Routes asynchronous background events (CWD changes, AI responses) to the correct UI components.
